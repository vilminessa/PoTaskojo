# PoTaskojo — прогресс

Системный монитор для Windows. Стек: **C++20 + CMake + MSVC, Dear ImGui
(docking) + Win32 + D3D11**.

| **C11. Обновления** | ✅ | Манифест — **ассет релиза** по фиксированному адресу `/releases/latest/download/`, который редиректит на последний релиз: без API, без токена, без лимитов. Подпись **ECDSA P-256 по точным байтам файла** — канонизации нет вовсе, поэтому нечему расходиться; публичный ключ вшит в бинарник, приватный живёт только в секрете CI, а шаг сборки дополнительно сверяет подписанный файл с ключом, извлечённым из исходника. Подпись проверяется **до** разбора; не доехавший манифест — это ошибка, а не «вы актуальны». Скачивание и проверка sha256 — в `update/`, подмена через **переименование запущенного образа** (Windows запрещает перезапись размапленного файла, но разрешает переименование), запуск замены — **после** снятия мьютекса одиночной копии, иначе новый процесс увидел бы занятый мьютекс и тут же вышел. В Settings разделы About и Updates; **авто-проверка при старте, раз в сутки**, молчит при ошибке (только в лог) и показывает диалог лишь когда вышло что-то более новое |
| **C12. Вектор подписи перегенерирован — подпись покрывает байты манифеста, а там лежат и домен, и имя exe. **История переписана**: 25 коммитов, содержимое деревьев, тексты сообщений и все 7 сообщений тегов; дерево `HEAD` не изменилось **байт-в-байт** (эталон `52e9f07c…` сверялся до и после), а архивы исходников старых тегов перестали содержать старое имя. Описание на Forgejo несло чужое имя — живёт вне git, поэтому его не ловили ни CI-гейт, ни аудит; выровнено с GitHub |

## Сборка

```powershell
cmake -G "Visual Studio 18 2026" -A x64 -S . -B build
cmake --build build --config Release
build\Release\potaskojo.exe
```

Данные: `%LOCALAPPDATA%\PoTaskojo\` (`settings.ini`, `logs\app.log`).
Для portable-режима создайте папку `PoTaskojoData\` рядом с exe.

CI: `.github/workflows/release.yml` — `verify` (сборка со `/WX` + тесты + сверка
`VERSION` с тегом + запрет посторонних упоминаний) → `build` (артефакт + sha256) →
`publish` (на тег `v*`) → SLSA-подпись → `gh attestation verify`.

Тесты локально:

```powershell
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Быстрый прогон через меню: `debug.bat` — сборка, тесты, аудит сходства, запуск
с внутренними флагами, git, скриншоты. `debug.bat 6` соберёт и протестирует,
`debug.bat 8 <путь>` прогонит аудит по архиву строк (путь можно задать и
переменной `RE_NOTES`), `debug.bat 5` — просто соберёт.

## Ключевые решения

- **Сбор данных**: worker-поток → staging → `shared_ptr` swap; UI-поток не
  блокируется на опросе.
- **Первый кадр**: окно не показывается, пока collectors и иконки не готовы —
  иначе видно «мигание» пустого окна.
- **Предохранители правил** (C5) — обязательны: авто-пауза при >N действий/мин,
  лимит дампов/час, отказ от protected/critical процессов.
- **Аудит сходства** сравнивает наши строки с дампами **без адресного
  префикса** — с префиксом дословное совпадение не ловится в принципе (так
  аудит какое-то время честно отдавал ноль). Нулевых дословных совпадений не
  бывает: допустимы только API и реестр Windows, имена системных процессов,
  состояния служб и общеупотребимые слова. Всё остальное переименовывается.
- **Обновления** (C11): подпись покрывает **точные байты файла манифеста**, а не
  пересериализованную форму — именно канонизация и есть источник багов вида
  «подпись не сходится, и непонятно почему». Первая строка несёт
  домен-разделитель, поэтому подпись, выданная для манифеста, непригодна для
  чего-то другого. **Authenticode не делаем**: сертификата издателя нет, а
  проверять собственный подписанный манифест своим же ключом дешевле и не
  требует PKI. **Инсталлятер отклонён** — распространяется один exe, обновление
  подменяет файл на месте.
- **Авто-проверка обновлений** (C11): раз в сутки, при старте, в фоновом потоке —
  первый кадр не ждёт сети. Ошибка остаётся в логе, а не в диалоге: недоступная
  сеть при запуске не должна прерывать человека каждый день. Диалог появляется
  только если вышло что-то более новое; человек, нажавший кнопку, получает ответ
  в любом случае. Скриптованные запуски (скриншоты, внутренние флаги) проверку
  подавляют, иначе модальное окно ляжет поверх кадра.
- **Миграция ключей настроек не нужна.** В `v0.0.1` и `v0.0.2` читались шесть
  старых ключей — `Window/Width`, `Window/Height`, `Window/AlwaysOnTop`,
  `Window/DefaultTab`, `Theme/LightTheme`, `Window/Maximized`; все они ушли в
  коммите «Scale the interface and polish the layout». Миграцию писать
  бессмысленно по двум независимым причинам: старый файл жил в
  `%LOCALAPPDATA%\TaskScope`, а новая сборка читает `%LOCALAPPDATA%\PoTaskojo` —
  другая папка, старый файл не открывается в принципе, — и `Window/Maximized`
  не имеет преемника, его значение просто отбрасывается.
- **Окно должно знать, кто его создал.** Указатель на `App` кладётся в
  `GWLP_USERDATA` в `WM_NCCREATE`. Без этого `wnd_proc` отдавал все сообщения
  `DefWindowProc`: кнопка закрытия уничтожала окно, а процесс жил вечно,
  ресайз не доходил до рендера, `WM_DPICHANGED` и мин. размер игнорировались,
  а коллбэк трея уходил в никуда. Держится на трёх проверках: закрытие
  завершает процесс, `close-to-tray` прячет (а не уничтожает) окно, и окно не
  даёт себя сжать ниже минимума.

## Известные ограничения

- Нет GPU-графиков (DXCore-счётчики) — в Information пока только базовые метрики.
- Нет per-process сетевых скоростей (нужен ETW) — только соединения.
- Startup: packaged-приложения (AppX) не перечисляются, только Run/папки.
- Сетевые графики: PDH `\Network Interface(*)` суммирует все NIC.
- **Снапшоты-история** (XPRESS) не реализованы — отложены.
- **Share-коды** правил/тем через буфер обмена не реализованы.
- **Выход занимает ~5 с на уровне процесса.** Окно исчезает за 0.1 с, так что
  для пользователя закрытие мгновенное; время уходит в статических
  деструкторах после последней строки лога (соединение потоков коллекторов).
  Повторный запуск это не блокирует: одиночная защита снимается вместе с
  окном — проверено запуском через 0.8 с после закрытия.
- **Путь «обновление найдено» не проверен end-to-end**, пока `v0.0.7` —
  последний релиз: `is_newer` возвращает false, диалог не появляется. Подпись,
  разбор, скачивание и подмена покрыты тестами и прогонялись вживую, но
  срабатывание реально подтвердится только на `v0.0.8`.
